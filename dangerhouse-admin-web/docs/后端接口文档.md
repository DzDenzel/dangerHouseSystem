# 危房智能检测系统 后端接口文档

接口以 `dangerhouse-backend/src/main/java/com/dz/dangerhouse/controller` 下的 Controller 定义为准，字段以 `dto/request`、`dto/response` 为准，前端调用位置为 `dangerhouse-admin-web/src/api`。

## 1. 基础约定

### 1.1 服务地址

| 环境 | Base URL | 来源 |
| --- | --- | --- |
| 开发 | `http://localhost:8080/api` | `.env.development` 的 `VITE_APP_BASE_API` |
| 生产 | `/api` | `.env.production` 的 `VITE_APP_BASE_API`，由反向代理转发到 8080 |

- 服务端口 8080，没有配置 `context-path`，所有接口路径均以 `/api` 开头。
- Swagger UI：`http://localhost:8080/swagger-ui.html`；OpenAPI JSON：`http://localhost:8080/api-docs`。
- 文档中出现的路径均为后端完整路径（含 `/api`），前端 `src/api` 里的 `url` 字段省去 `VITE_APP_BASE_API` 前缀。

### 1.2 认证方式

| 项 | 值 |
| --- | --- |
| 请求头 | `Authorization: Bearer <token>` |
| Token 来源 | `POST /api/auth/login` 响应 `data.token` |
| 普通登录有效期 | 3600 秒（`jwt.expiration`） |
| 记住我有效期 | 259200 秒（`jwt.remember-expiration`），请求时 `rememberMe=true` |
| 前端存储 | `localStorage` 的 `token` 键（`src/utils/request.ts`） |
| 失效方式 | `POST /api/auth/logout` 把当前 token 写入 Redis 黑名单，剩余有效期内立即失效 |

前端请求拦截器的行为：请求 URL 中包含 `/auth/` 时不附加 `Authorization` 头（`const isAuthRequest = requestUrl.includes("/auth/")`），其余请求自动带上。

这带来一个实际影响：`POST /api/auth/logout` 的 URL 含 `/auth/`，前端不会附带 token，而后端 `AuthServiceImpl.logout` 从 `Authorization` 头取 token，取不到会抛 `IllegalArgumentException`，返回 `code=400`、`message="缺少有效的 Authorization 令牌"`，token 不会进入黑名单。调用该接口时需要显式带上请求头：

```
POST /api/auth/logout HTTP/1.1
Host: localhost:8080
Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...
```

服务端鉴权链路：`JwtAuthenticationFilter` 解析并校验 token（格式错误、签名无效、过期、命中黑名单均视为未登录），`SecurityConfig` 做 URL 级拦截，Controller 上的 `@PreAuthorize` 做方法级拦截。

URL 级规则（`SecurityConfig.securityFilterChain`）：

| 路径 | 规则 |
| --- | --- |
| `/api/auth/**`、`/api/files/**`、`/uploads/**`、`/swagger-ui/**`、`/swagger-ui.html`、`/api-docs/**` | `permitAll` |
| `/api/admin/**` | `hasRole('ADMIN')` |
| 其他所有请求 | `authenticated()` |

方法级规则统一写作 `hasAnyRole('USER','INSPECTOR','ADMIN')`、`hasRole('ADMIN')` 或 `hasAnyRole('INSPECTOR','ADMIN')`，本文在单个接口的"权限"一栏标注。二者需同时满足。

### 1.3 统一响应结构

所有 JSON 接口返回 `Result<T>`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | Integer | 200 表示成功，其余为错误码 |
| `message` | String | 提示信息，成功时通常为 `success` 或业务文案 |
| `data` | T | 业务数据，无数据时为 `null` |
| `timestamp` | Long | 服务端时间戳，秒级 |
| `requestId` | String | 请求唯一标识（32 位 UUID，无连字符） |

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 12,
    "username": "zhangsan",
    "roles": ["INSPECTOR"]
  },
  "timestamp": 1758350370,
  "requestId": "9f2c1d7a4b6e4c8f9a0b1c2d3e4f5a6b"
}
```

失败响应：

```json
{
  "code": 403,
  "message": "没有权限访问该建筑档案",
  "data": null,
  "timestamp": 1758350371,
  "requestId": "3c8b7a1d5e2f4a6b8c0d1e2f3a4b5c6d"
}
```

HTTP 状态码与 `code` 并不同步：`BusinessException` 由全局处理器转换为 **HTTP 200** + `body.code=4xx/500`；只有参数校验异常（HTTP 400）、`SecurityConfig` 直接拒绝（HTTP 401/403）、方法不支持（HTTP 405）会同时改 HTTP 状态码。前端 axios 响应拦截器按 `body.code` 判定成功（`200`/`0`/`"200"`/`"0"`/`"00000"` 视为成功），因此判断结果一律以 `code` 为准。

### 1.4 分页结构

分页接口的 `data` 为 `PageResponse<T>`（`dto/response/PageResponse.java`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `records` | Array | 当前页数据列表 |
| `total` | Long | 总记录数 |
| `current` | Long | 当前页码 |
| `size` | Long | 每页条数 |
| `pages` | Long | 总页数 |

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [
      { "id": 8, "name": "幸福小区 3 号楼", "address": "杭州市西湖区文一西路 100 号" }
    ],
    "total": 27,
    "current": 1,
    "size": 10,
    "pages": 3
  },
  "timestamp": 1758350372,
  "requestId": "ab12cd34ef56ab78cd90ef12ab34cd56"
}
```

分页请求参数统一为 `page`（页码，从 1 开始，默认 1）与 `size`（每页条数，默认 10）。`GET /api/buildings` 额外兼容 `pageNo`，当 `pageNo` 存在时优先使用。

### 1.5 角色

| 角色码 | 角色 ID | 说明 |
| --- | --- | --- |
| `ADMIN` | 1 | 管理员，管理后台账号，可访问 `/api/admin/**`、用户管理 |
| `INSPECTOR` | 2 | 检测员，可创建建筑档案、删除建筑与检测记录 |
| `USER` | 3 | 普通用户，只能访问属于自己的建筑、检测、报告数据 |

一个账号可以同时拥有多个角色，`roles` 字段恒为数组。

数据隔离规则（后端在各 Service 内实现，不是权限注解）：

| 资源 | USER 角色的可见范围 |
| --- | --- |
| 建筑 | `ownerUserId` 等于当前用户的建筑；其他建筑访问返回 `403` |
| 检测记录 | `userId` 等于当前用户的检测；列表自动追加该过滤条件 |
| 报告 | 报告所属检测记录的 `userId` 等于当前用户 |
| 用户管理 | 无权访问（接口权限为 `ADMIN`） |

### 1.6 登录端隔离

`POST /api/auth/login` 的 `clientType` 必填，取值为 `WEB`（管理后台）或 `APP`（移动端），服务端大小写不敏感并做 trim。校验规则：

| clientType | 账号角色 | 结果 |
| --- | --- | --- |
| `WEB` | 含 `ADMIN` | 登录成功 |
| `WEB` | 不含 `ADMIN` | `403 当前账号无权登录 Web 后台，请使用管理员账号` |
| `APP` | 含 `ADMIN` | `403 管理员账号仅允许登录 Web 后台，不允许登录 App` |
| `APP` | 不含 `ADMIN` | 登录成功 |
| 其他值或空 | — | `400 不支持的登录端类型`（空值触发校验 `400 登录端类型为必填项`） |

管理后台前端固定传 `WEB`（`src/api/auth/index.ts` 中 `clientType: data.clientType ?? "WEB"`）。

### 1.7 时间格式与文件上传

| 项 | 约定 |
| --- | --- |
| 响应中的时间 | `LocalDateTime` 序列化为 ISO-8601 无时区字符串，如 `2026-09-20T15:59:30` |
| 请求中的日期 | 查询参数用 `yyyy-MM-dd`，如 `startDate=2026-09-01` |
| `Result.timestamp` | 秒级 Unix 时间戳 |
| 单文件上限 | 10MB（`spring.servlet.multipart.max-file-size`） |
| 单请求上限 | 50MB（`spring.servlet.multipart.max-request-size`） |
| 文件访问 | 本地存储时文件相对路径存库，响应中通过 `file.upload.url-prefix` 拼成可访问 URL，形如 `http://localhost:8080/uploads/images/2026/09/20/xxx.jpg`；启用 OSS 后返回 OSS 签名 URL |

### 1.8 错误码

| code | 常见触发场景 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数校验失败、密码/用户名/手机号格式非法、缺少登录端类型、检测未完成就生成报告、上传图片为空 |
| 401 | 未携带或携带无效 token（Security 拦截，`登录状态已失效，请重新登录`）、登录密码错误（`密码错误，请重新输入`） |
| 403 | 角色不足（`当前账号无权访问该功能`）、账号被禁用、跨用户访问建筑/检测/报告、Web 端非管理员登录 |
| 404 | 建筑、检测任务、报告、用户不存在；登录时账号未注册 |
| 405 | HTTP 方法不支持 |
| 500 | 未指定 code 的业务异常（`BusinessException` 默认 500）与未捕获异常（`服务器内部错误`） |

`SecurityConfig` 直接拒绝时的响应体不含 `timestamp`/`requestId`：

```json
{"code":401,"message":"登录状态已失效，请重新登录","data":null}
```

## 2. 健康检查

### 2.1 GET /api/health

接口状态、数据库、AI 服务状态快照。

| 项 | 值 |
| --- | --- |
| 权限 | 任意已登录角色（Controller 上没有 `@PreAuthorize`，但 `/api/health` 不在 `permitAll` 名单内，需携带有效 token） |
| 请求参数 | 无 |

响应字段（`HealthCheckResponse`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | String | 服务状态，固定 `UP` |
| `database` | String | 数据库状态，固定 `OK` |
| `aiService` | String | AI 服务状态，固定 `OK` |
| `message` | String | 预留字段，当前返回 `null` |

响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "status": "UP",
    "database": "OK",
    "aiService": "OK",
    "message": null
  },
  "timestamp": 1758350373,
  "requestId": "77aa11bb22cc33dd44ee55ff66778899"
}
```

返回值为固定快照，不会真正探测数据库与 Python AI 服务。

## 3. 认证授权

### 3.1 POST /api/auth/login

| 项 | 值 |
| --- | --- |
| 权限 | 无需认证（`permitAll`） |
| Content-Type | `application/json` |

请求体（`LoginRequest`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `account` | String | 是 | 账号，支持用户名、手机号、邮箱三种形式，服务端自动识别 |
| `password` | String | 是 | 密码 |
| `rememberMe` | Boolean | 否 | 是否记住我，`true` 时 token 有效期 3 天，默认 `false`（1 小时） |
| `clientType` | String | 是 | 登录端，`WEB` 或 `APP` |

请求示例：

```json
{
  "account": "zhangsan",
  "password": "123456",
  "rememberMe": false,
  "clientType": "WEB"
}
```

响应字段（`LoginResponse`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Long | 用户 ID |
| `token` | String | JWT，后续请求放在 `Authorization: Bearer <token>` |
| `roles` | String[] | 角色码数组，如 `["ADMIN"]`、`["USER"]`、`["INSPECTOR"]` |
| `username` | String | 用户名 |
| `phone` | String | 手机号 |
| `email` | String | 邮箱，未设置为 `null` |
| `nickname` | String | 昵称 |
| `avatar` | String | 头像 URL |
| `lastLoginTime` | String | 上次登录时间 |
| `createdAt` | String | 注册时间 |
| `updatedAt` | String | 更新时间 |
| `status` | Integer | 1 正常，0 禁用 |

响应示例：

```json
{

  "message": "success",
  "data": {
    "id": 1,
```

错误响应：

| 场景 | code | message |
| --- | --- | --- |
| 账号为空 | 400 | `account: 账号为必填项` |
| 密码为空 | 400 | `password: 密码为必填项` |

| 登录端不匹配 | 403 | `当前账号无权登录 Web 后台，请使用管理员账号` |

登录成功后服务端会更新 `lastLoginTime` 与 `lastLoginIp`。

### 3.2 POST /api/auth/register

| 项 | 值 |
| --- | --- |
| 权限 | 无需认证（`permitAll`） |
| Content-Type | `application/json` |

请求体（`RegisterRequest`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | String | 是 | 以字母开头，只能包含字母、数字、下划线，长度 4-20 位 |

| `phone` | String | 是 | 11 位手机号，需匹配 `^1[3-9]\d{9}$` |

```json

  "username": "lisi",
```

响应字段（`RegisterResponse`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Long | 新用户 ID |
| `username` | String | 用户名 |
| `phone` | String | 手机号 |
| `role` | String | 固定 `USER` |
| `message` | String | 固定 `注册成功` |
| `createTime` | String | 创建时间 |

响应示例：

```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "id": 18,
    "username": "lisi",
    "phone": "13900139000",
    "role": "USER",
    "message": "注册成功",
    "createTime": "2026-09-20T16:02:11"
  },
  "timestamp": 1758350531,
  "requestId": "5f4e3d2c1b0a99887766554433221100"
}
```

错误响应（均为 HTTP 400）：

| 场景 | message |
| --- | --- |
| 用户名为空 | `用户名为必填项` |
| 用户名格式非法 | `用户名需以字母开头，只能包含字母、数字、下划线，长度为 4-20 位` |
| 手机号为空 | `手机号为必填项` |
| 手机号格式非法 | `请输入正确的 11 位手机号` |
| 密码为空 | `密码为必填项` |
| 密码过短 | `密码长度不能少于 6 位` |
| 用户名已存在 | `该用户名已被使用，请更换后重试` |
| 手机号已注册 | `该手机号已经注册过账户，请直接登录` |

### 3.3 POST /api/auth/logout

把当前 token 写入黑名单，剩余有效期内该 token 立即失效。

| 项 | 值 |
| --- | --- |
| 权限 | 无需认证即可进入方法，但方法内要求 `Authorization` 头 |
| 请求参数 | 无 |
| 响应 | `data` 为 `null`，`message` 为 `退出登录成功` |

```http
POST /api/auth/logout HTTP/1.1
Host: localhost:8080
Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...
```

```json
{
  "code": 200,
  "message": "退出登录成功",
  "data": null,
  "timestamp": 1758350600,
  "requestId": "0011223344556677889900aabbccddee"
}
```

缺少或格式错误的 `Authorization` 头时返回 `code=400`、`message="缺少有效的 Authorization 令牌"`。

### 4.2 PUT /api/user/profile

更新当前登录用户的信息，只能改自己的数据（用户 ID 取自 token）。

| 项 | 值 |
| --- | --- |
| 权限 | `hasAnyRole('USER','INSPECTOR','ADMIN')` |
| Content-Type | `application/json` |

请求体（`UserUpdateRequest`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `phone` | String | 否 | 手机号，需匹配 `^1[3-9]\d{9}$`，且不能被其他账号占用 |
| `email` | String | 否 | 邮箱，格式校验，且不能被其他账号占用 |
| `nickname` | String | 否 | 昵称 |
| `avatar` | String | 否 | 头像 URL |
| `newPassword` | String | 否 | 新密码，非空时一并更新，长度不少于 6 位 |
| `id` | Long | 否 | DTO 中存在，服务端忽略，以 token 中的用户 ID 为准 |

## 12. 数据字典

### 12.1 风险等级（`RiskLevel` 枚举）

| code | 兼容码 | 名称 | 损伤占比区间 | 颜色 |
| --- | --- | --- | --- | --- |
| `A` | `LOW` | 低风险 | < 5% | `#28A745` |
| `B` | `MEDIUM` | 中风险 | 5% - 15% | `#FFC107` |
| `C` | `HIGH` | 高风险 | 15% - 30% | `#FD7E14` |
| `D` | `CRITICAL` | 严重风险 | ≥ 30% | `#DC3545` |

区间左闭右开：损伤占比等于 15% 判为 `C`，等于 30% 判为 `D`。

### 12.2 检测状态

| 状态 | 说明 | 可执行操作 |
| --- | --- | --- |
| `CREATED` | 任务已创建，未上传图片 | 上传图片、取消、删除 |
| `READY` | 图片已就绪，可启动检测 | 启动检测、取消、删除 |
| `PROCESSING` | AI 分析中 | 删除 |
| `COMPLETED` | 检测完成，已有风险等级 | 生成报告、删除 |
| `FAILED` | 检测失败，`errorMessage` 有原因 | 重新启动检测、删除 |
| `CANCELLED` | 已取消 | 删除 |
