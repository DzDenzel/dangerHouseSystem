## 1. 接口规范

### 1.0 v3.0 更新说明

- 检测接口按任务状态流工作，不再要求同步返回最终结果
- 检测详情新增 `username`、`images`、`report`、`errorMessage`
- 报告生成接口返回 `reportId`、`reportNo`、`downloadUrl`、`status`、`createdAt`
- 报告下载建议前端在 Web 端使用浏览器直连下载，避免 XHR 被浏览器插件拦截
- 检测状态统一为 `CREATED / READY / PROCESSING / COMPLETED / FAILED / CANCELLED`

### 1.1 统一响应结构

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1710000000,
  "requestId": "c8e3f1b1..."
}
```

| 字段        | 类型      | 说明           |
|-----------|---------|--------------|
| code      | Integer | 响应码，200 表示成功 |
| message   | String  | 响应消息         |
| data      | Object  | 响应数据         |
| timestamp | Long    | 时间戳（秒）       |
| requestId | String  | 请求唯一标识       |

### 1.2 DTO 规范

- 请求 DTO：`com.dz.dangerhouse.dto.request`
- 响应 DTO：`com.dz.dangerhouse.dto.response`
- 分页响应：`PageResponse<T>`
- 查询条件：`QueryRequest`

### 1.3 分页响应结构

```json
{
  "records": [],
  "total": 100,
  "current": 1,
  "size": 10,
  "pages": 10
}
```

| 字段      | 类型    | 说明      |
|---------|-------|---------|
| records | Array | 当前页记录列表 |
| total   | Long  | 总记录数    |
| current | Long  | 当前页码    |
| size    | Long  | 每页数量    |
| pages   | Long  | 总页数     |

### 1.4 认证方式

- Header：`Authorization: Bearer {token}`
- Token 由登录接口获取，默认 24 小时有效

## 2. 认证授权

### 2.1 用户登录

- **路径**：`POST /api/auth/login`
- **权限**：无需
- **描述**：用户名/手机号/邮箱登录

**请求体**：`LoginRequest`

```json
{
  "account": "admin",
  "password": "123456"
}
```

| 字段       | 类型     | 必填 | 说明         |
|----------|--------|----|------------|
| account  | String | 是  | 用户名/手机号/邮箱 |
| password | String | 是  | 密码         |

**响应**：`Result<LoginResponse>`

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "roles": [
      "ADMIN"
    ],
    "username": "admin",
    "phone": "13800138000",
    "email": "admin@example.com",
    "nickname": "管理员",
    "avatar": "/uploads/avatar/1.jpg",
    "lastLoginTime": "2026-03-16T10:00:00",
    "createdAt": "2026-01-01T00:00:00",
    "updatedAt": "2026-03-16T10:00:00",
    "status": 1
  }
}
```

### 2.2 用户注册

- **路径**：`POST /api/auth/register`
- **权限**：无需
- **描述**：新用户注册

**请求体**：`RegisterRequest`

```json
{
  "username": "testuser",
  "password": "123456",
  "phone": "13800138001",
  "role": "USER"
}
```

| 字段       | 类型     | 必填 | 说明         |
|----------|--------|----|------------|
| username | String | 否  | 用户名        |
| password | String | 否  | 密码         |
| phone    | String | 否  | 手机号        |
| role     | String | 否  | 角色，默认 USER |

**响应**：`Result<RegisterResponse>`

```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "id": 2,
    "username": "testuser",
    "phone": "13800138001",
    "role": "USER",
    "message": "注册成功",
    "createTime": "2026-03-16T10:00:00"
  }
}
```

### 2.3 检查用户名

- **路径**：`GET /api/auth/check-username/{username}`
- **权限**：无需
- **描述**：检查用户名是否已被使用

**路径参数**：
| 参数 | 类型 | 说明 |
|------|------|------|
| username | String | 用户名 |

**响应**：`Result<Boolean>`

```json
{
  "code": 200,
  "message": "success",
  "data": true
}
```

- `true`：用户名可用
- `false`：用户名已被使用

## 5. 检测任务

### 5.1 创建任务

- **路径**：`POST /api/detections`
- **权限**：需要登录
- **描述**：创建一个新的空检测任务，并关联指定建筑

**请求参数**（表单）：

| buildingId | Long | 是 | 建筑ID |

**响应**：`Result<DetectionResultResponse>`

  "code": 200,
  "message": "检测任务创建成功",
  "data": {

### 5.2 上传图片

- **路径**：`POST /api/detections/{id}/images`
- **权限**：需要登录
- **描述**：为指定的检测任务上传图片（支持多张，最多10张）

返回的 `imagePath` / `resultImagePath` 为可直接访问的文件地址：

- OSS 启用时：返回 OSS 完整访问 URL
- OSS 关闭时：返回本地映射 URL，如 `/uploads/images/...`

**路径参数**：
| 参数 | 类型 | 说明 |
|------|------|------|
| id | Long | 检测任务ID |

| 字段 | 类型 | 说明 |
|------|------|------|
| images | File[] | 图片文件列表 |

**响应**：`Result<List<ImageInfo>>`

```json
{
  "code": 200,
  "message": "上传成功",
  "data": [
    {
      "id": 1,
      "imagePath": "https://dangerhouse-files.oss-cn-hangzhou.aliyuncs.com/images/2026/03/19/xxx.jpg",
      "resultImagePath": null,
      "imageType": "ORIGINAL",

    }
  ]
}
```

## 7. 报告管理

说明：

- 报告文件由 `PdfReportGenerator` 生成后，通过统一文件存储服务上传。
- 数据库中的 `filePath` 保存的是存储路径（如 OSS objectKey 或本地相对路径），不是下载接口地址。
- 报告下载统一通过 `GET /api/reports/{id}/download` 获取，兼容 OSS 与本地双模式。

### 7.1 生成报告

- **路径**：`POST /api/reports/generate`
- **权限**：需要登录
- **描述**：生成报告文件

**请求体**：`GenerateReportRequest`

```json
{
  "detectionId": 1,
  "format": "PDF"
}
```

| 字段          | 类型     | 必填 | 说明           |
|-------------|--------|----|--------------|
| detectionId | Long   | 是  | 检测任务ID       |
| format      | String | 是  | 格式（PDF/DOCX） |

**响应**：`Result<GenerateReportResponse>`

```json
{
  "code": 200,
  "message": "报告生成成功",
  "data": {
    "reportId": 1,
    "reportNo": "RPT20260316001"
  }
}
```

### 7.2 获取报告详情

- **路径**：`GET /api/reports/{id}`
- **权限**：需要登录
- **描述**：获取报告详情

**路径参数**：
| 参数 | 类型 | 说明 |
|------|------|------|
| id | Long | 报告ID |

**响应**：`Result<ReportResponse>`

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "detectionId": 1,
    "buildingId": 1,
    "reportNo": "RPT20260316001",
    "filePath": "reports/2026/03/19/RPT20260316001.pdf",
    "fileType": "PDF",
    "generatedAt": "2026-03-16T10:00:00"
  }
}
```

### 7.3 下载报告

- **路径**：`GET /api/reports/{id}/download`
- **权限**：需要登录
- **描述**：下载报告文件

**路径参数**：
| 参数 | 类型 | 说明 |
|------|------|------|
| id | Long | 报告ID |

**响应**：文件流（`application/pdf`）

说明：

- 下载接口内部通过统一文件存储服务读取文件字节，不要求报告一定存在于本地磁盘。
- 当前文件名固定按 `reportNo.pdf` 返回。

## 附录

### A. 请求示例

#### 登录获取Token

```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"account":"admin","password":"123456"}'
```

#### 创建建筑档案

```bash
curl -X POST http://localhost:8080/api/buildings \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"name":"测试建筑","address":"北京市朝阳区"}'
```

#### 上传检测图片

```bash
curl -X POST http://localhost:8080/api/detections/1/images \
  -H "Authorization: Bearer {token}" \
  -F "images=@/path/to/image1.jpg" \
  -F "images=@/path/to/image2.jpg"
```

### B. 前端集成说明

1. **认证流程**：登录成功后，将 `token` 存储在 localStorage 或 cookie 中，后续请求在 Header 中携带
   `Authorization: Bearer {token}`

2. **角色判断**：登录响应中的 `roles` 数组包含用户所有角色，可通过 `isAdmin()` 方法判断是否为管理员

3. **分页处理**：列表接口返回 `PageResponse`，包含 `records`、`total`、`current`、`size`、`pages` 字段

4. **文件上传**：使用 `multipart/form-data` 格式，图片上传接口支持多文件

5. **错误处理**：根据 `code` 字段判断请求是否成功，`code !== 200` 时显示 `message` 中的错误信息
