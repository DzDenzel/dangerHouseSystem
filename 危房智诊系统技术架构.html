Scope

系统边界与工程模块

App
dangerhouse-mobile-app
Flutter 跨端应用，面向普通用户与检测员，负责登录、建筑建档、现场拍摄、AI 检测、结果和报告查看。
Web
dangerhouse-admin-web
Vue 3 管理后台，面向管理员，负责仪表盘、建筑管理、检测记录、用户/日志等后台管理能力。
API
dangerhouse
Spring Boot 后端服务，统一承接鉴权、权限、业务编排、数据访问、缓存、文件、报告和 AI 服务调用。
AI
dangerhouse-ai-service
FastAPI + PyTorch 推理服务，负责裂缝检测、风险评级、标注图输出与多图聚合分析。
一句话：这是一个“移动端现场采集 + Web 后台管理 + 后端业务中台 + AI 推理微服务”的前后端分离系统。

Web Runtime Architecture

Web 端运行架构：路由、权限、请求

路由层

  • createWebHashHistory()，适合静态部署与反向代理场景。
  • 基础路由包含登录、首页、401/404、报告隐藏页。
  • 业务路由由 permission Store 根据角色过滤后动态添加。
  • 本地 fallback 菜单包含建筑管理、检测管理、系统管理。

权限层

  • 登录 Token 存储在 localStorage。
  • 路由守卫检查 Token 与角色，未登录跳转 /login。
  • 后台强约束 ADMIN：非管理员获取用户信息后会被清 Token 并拒绝进入。
  • VITE_USE_BACKEND_MENUS 控制是否从后端菜单加载。

请求层

  • Axios 实例统一 baseURL、超时 50 秒、JSON 请求头。
  • 非认证接口自动注入 Authorization: Bearer token。
  • 统一识别业务成功码 200 / 0 / 00000。
  • 401 弹窗提示重新登录，普通错误用 Element Plus message 展示。

Flutter App

App 端框架拆解

跨端框架

  • Flutter + Dart，SDK 约束 >=3.2.0 <4.0.0。
  • 支持 Android、iOS、Web、Windows 工程目录。
  • Material Design 与自定义主题 app_theme。
  • 摄像头、相册、权限、路径、本地文件能力完整接入。

状态与路由

  • flutter_riverpod + Provider / Notifier 管理应用状态。
  • go_router 声明式路由与登录重定向。
  • TokenManager 维护 Token 与过期判断。
  • appContainer 用于全局状态访问与会话过期处理。

数据与网络

  • DioClient 封装 GET/POST/PUT/DELETE/UPLOAD。
  • AuthInterceptor 自动注入 Bearer Token。
  • json_serializable 生成模型序列化代码。
  • Repository + RemoteDataSource 隔离接口细节。
App 基础 API 地址通过编译参数 APP_BASE_URL 控制，默认 http://localhost:8080；业务接口常量统一集中在 ApiConstants。

App 端页面与分层架构

核心页面路径

路径页面能力

/home首页统计、入口聚合。

分层方式

  • core：网络、路由、错误、主题、常量、工具、Token。
  • data：models、sources、repositories，负责 DTO 与远端 API。
  • domain：Task、DetectionReport 等领域实体。
  • presentation：页面与自定义绘制，例如检测结果框绘制。
  • providers：认证、检测、建筑、仪表盘、离线检测等状态。

会话保护链路

  • 公开路径：登录、注册、用户名/手机号检查、健康检查。
  • 非公开请求先检查 Token 是否过期，过期时触发会话失效处理。
  • 401 响应会自动导航到登录页，并显示“登录已过期”。
  • 手动退出时会短暂抑制重复 401 跳转，避免体验抖动。

AI Service

AI 检测服务框架拆解

服务层

  • FastAPI 应用，服务标题 Building Damage Detection API，版本 2.1.0。
  • Uvicorn 启动，监听 0.0.0.0:8000。
  • CORS 全开放，方便后端/调试端联调。
  • Pydantic 定义请求响应模型，便于与 Java DTO 对齐。

模型层

  • TorchVision fasterrcnn_resnet50_fpn_v2。
  • 分类头替换为 2 类：背景 + 裂缝。
  • 权重路径 ./runs_detect/best.pt。
  • 设备自动选择 cuda 或 cpu。

算法层

  • OpenCV 解码、绘制红色检测框与置信度。
  • 单图计算裂缝数、面积占比、平均置信度。
  • 多图使用 DBSCAN 对中心点做空间去重。
  • 输出 Base64 结果图，后端再保存为文件。
POST /api/v1/detect_damage multipart/form-data: images: UploadFile[] score_thr: float = 0.3 response.data: analysis: { severityLevel, damageRatio, crackCount, confidenceScore, recommendation } detections: [{ type: "crack", confidence, bbox, center, width, height, area }] imageResults: [{ filename, detections, resultImage, analysis }] resultImage: base64
AI Risk Logic

AI 检测与风险评级逻辑

1
读取图片UploadFile → bytes → NumPy → OpenCV BGR。
2
预处理BGR 转 RGB，转换 Tensor，归一化到 0-1。
3
模型推理Faster R-CNN 输出 boxes / scores。
4
阈值过滤默认 score_thr=0.3。
5
结果绘制OpenCV 画框，编码 JPG Base64。
6
风险聚合DBSCAN 去重后取更高风险维度。

风险等级阈值

等级裂缝数量损伤比例建议
A< 3< 5%结构安全，无需处理。
B≥ 3≥ 5%存在轻微损伤，建议定期观察。
C≥ 6≥ 15%局部危房，建议修缮加固。
D> 10> 30%立即停止使用并由专业机构鉴定。

后端如何消费 AI 结果

  • 后端将上传图片交给 AI 服务，并接收整体分析与单图结果。
  • Base64 结果图通过 FileStorageService.saveBase64Image 保存。
  • 聚合字段写回 detection：裂缝数、损伤比例、风险等级、置信度、检测时间。
  • 单图结果路径写回 image.result_image_path，供 App/Web 展示。

Storage / Cache / Logs

存储、缓存、日志与后台任务

文件存储

  • FileStorageService 抽象本地/OSS。
  • 本地默认 uploads，URL 前缀 /uploads。
  • 支持图片、结果图、PDF、Base64 图片、临时文件。
  • OSS 由 ALIYUN_OSS_ENABLED 等环境变量控制。

Redis 缓存

  • JSON 序列化，支持 Java 8 时间类型。
  • 缓存穿透：空值缓存。
  • 缓存击穿：分布式锁 + Lua 解锁。
  • 缓存雪崩：TTL 随机抖动。

操作日志

  • @Log 注解标记业务操作。
  • OperationLogAspect AOP 采集参数、结果、IP、状态。
  • operationLogExecutor 异步写入。
  • 管理员可通过 /api/admin/operation-logs 查询。

定时清理

  • @EnableScheduling 开启调度。
  • 每月 1 日 03:00 执行。
  • 清理逻辑删除超过 90 天的数据。
  • 覆盖 image、report、detection、building。
缓存设计已经不只是“加 Redis”：代码中明确处理了穿透、击穿、雪崩和 Redis 不可用时的降级回源，这一点在答辩或项目介绍里很加分。

Professional Summary

系统专业总结与可优化方向

架构成熟点

  • 多端职责清晰：App 现场业务、Web 管理后台、后端统一编排、AI 独立推理。
  • 权限模型完整：USER / INSPECTOR / ADMIN 对入口和数据范围都有约束。
  • 检测链路完整：建档、上传、AI、结果、报告形成闭环。
  • 缓存、日志、定时清理、文件存储抽象等工程能力已具备。

联调关注点

  • Web 模板遗留接口与后端现行接口需要保持文档同步。
  • AI 服务权重 best.pt 不存在时会退化为初始模型，应部署前校验。
  • 文件预览路径当前放行，生产环境建议结合访问控制和签名 URL。
  • 默认数据库/Redis 密码在配置中直接出现，生产应全部环境变量化。

后续增强

  • 引入统一 OpenAPI 生成前端/移动端类型，减少接口漂移。
  • AI 推理任务可异步化，增加队列与进度通知。
  • 报告生成可扩展 DOCX 模板和电子签章。
  • 补充 Docker Compose，一键启动 MySQL、Redis、后端、AI 和 Web。

这个系统的核心价值不是单点技术，而是把“现场采集、后台管理、业务数据、AI 研判、报告交付”串成了一条完整的工程闭环。
